# 01 · 开篇：Agent Harness 到底是什么

> 本篇目标：不写一行代码，先把三个问题聊透——**agent 是什么？harness 是什么？为什么值得花一周时间读 DSH 的源码？** 读完后你应该已经把它在你自己的电脑上跑起来了。

## 从一个问题开始

打开一个 AI 编程助手，输入："帮我看看这个仓库的测试为什么挂了。"

十秒后它回复：**"仓库里找了这几处可疑的地方，我先读了 `utils.ts` 和两个测试文件，跑了一遍 `npm test`，错误在第五行，已修好。"**

请问这段对话里，是谁读的文件？谁执行的命令？

答案是：**模型什么都没做**。大模型 API 只是一个函数——文本进去、文本出来，它不能打开文件、不能执行 shell、甚至记不住上一句话（除非你把上一句再发一遍）。真正"长了手"的，是围着模型的另一层软件：

- 它把你的请求包装成 prompt 发给模型；
- 模型说"我想运行 `npm test`"，是这层软件去真的执行了命令；
- 命令输出几万行，是这层软件决定塞多少回给模型；
- 执行 `rm -rf` 之前弹窗问你，也是这层软件干的。

这一层软件，就叫 **harness**——原意是马的挽具、飞行员的安全带：束缚与赋能同一个词。它给聪明但没有身体的大脑装上手脚、记忆、感官和刹车。

用一句话给出本书反复使用的定义：

> **Agent harness = 把一个"只会生成文本的模型"变成一个"能持续行动、能记住历史、能安全干活的智能体"的全部基础设施。**

## 三组容易混淆的概念

第一次接触这个领域的人，请先分清三组词：

| 概念 | 是什么 | 例子 |
|---|---|---|
| **Model（模型）** | 文本进文本出的推理引擎 | DeepSeek V4、GPT、Claude |
| **Agent（智能体）** | "模型 + 循环 + 工具"构成的一个活动实体；一次会话里的那个"干活者" | 你对话框背后的那个助手实例 |
| **Harness（挽具）** | 生产、驱动、约束这些 agent 的整个软件系统 | Claude Code、Codex CLI、以及本书的 DeepSeek Harness |

区分 agent 与 harness 的方法很简单：**agent 是一轮一轮死掉的，harness 是一直活着的**。你关掉窗口，这次会话的 agent 就结束了；而 harness 还在管理它的日志、它的兄弟 agent、下一批任务。

## 为什么现在值得学 harness

三个理由，按说服力递增：

1. **模型在趋同，体验在分化。** 各家旗舰模型的编程能力差距在收窄，但同一个模型接到不同 harness 里，产出质量天差地别——上下文怎么裁剪、工具结果怎么截断、什么时候打断、出错怎么重试，这些 harness 决策直接决定成败。
2. **这是新岗位的基础设施。** 无论叫 AI 工程师还是 Agent 工程师，工作的本质都是设计循环、编排上下文、管住权限——全是 harness 的内功。
3. **最好的教材刚刚开源。** 2026 年 8 月，DeepSeek 开源了自家的 agent harness（MIT 协议）：55 个子包、2472 个 TypeScript 源文件、自带 unusually candid 的架构文档——几乎没有哪个同体量的系统愿意把自己的架构决策写得这么明白。这就是本书的主角 **DeepSeek Harness（DSH）**。

## DSH 自我介绍的三句话

来自它自己仓库 [README.zh.md](https://github.com/deepseek-ai/deepseek-harness)：

1. 它是 DeepSeek AI 官方开发的开源 **agent harness**；
2. 架构信条是 **"一切皆插件"**——包括模型适配器、工具注册表、会话日志，甚至 **agent 循环本身也是插件**，所以每一部分都可以被配置替换；
3. 底层由 **Cordis** 框架驱动，其设计有一篇论文背书：*A Programming Paradigm for Spatiotemporal Composability*（时空可组合的编程范式）。

第三句话现在看不懂没关系，第 08 篇会专门拆 Cordis。现在只需要记住一个直觉：**DSH 里没有"内核 + 插件"的分层，只有插件树本身**——连你以为最核心的那个 while 循环，都只是树上普通的一个节点。这是它与绝大多数 harness 的根本差异，也既是它最大的优雅，也是它最大的代价（第 15 篇细算这笔账）。

先感受一下它的规模，后面每一篇你都会深入其中一块：

```
deepseek-harness/
├── apps/
│   ├── cli/        ← npx @deepseek-ai/dsh 的入口
│   └── web/        ← 浏览器前端（React）
├── packages/       ← 55 个子包
│   ├── core/       ← ★ 心脏地带：agent-loop / session / tools / system-prompt
│   ├── llm/        ← 大模型适配层（deepseek 直连 + 多供应商通用适配器）
│   ├── fs|shell|sandbox/ ← 文件、命令行、沙箱等能力层
│   ├── boot|bundle/ ← 启动器与发行组合包
│   ├── client|host/ ← 前后端协议与 HTTP 载体
│   └── subagent|todo|goal|skill|... ← 认知增强层
├── vendor/cordis/  ← 以源码方式内置的插件框架
├── native/         ← 一个 C 语言写的 Linux 沙箱启动器（landlock）
├── docs/           ← 官方架构文档（含中文，质量很高）
└── examples/       ← 示例插件
```

## 现在就把它跑起来

体验是最好的地基。三条命令（任选其一）：

```sh
# 方式一：什么都不装，直接跑 Web 版（需要 Node.js ≥ 22）
npx @deepseek-ai/dsh web
# 默认在 http://127.0.0.1:3080 打开浏览器界面；--no-open 可只起服务不开浏览器

# 方式二：从源码跑
git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness && pnpm install && pnpm run build
pnpm dsh web

# 方式三：看一眼你的机器上实际长成的"插件树"
npx @deepseek-ai/dsh --profile web --dump-config
```

第三条命令特别值得一提：它会打印出这个产品由哪些插件组成、每个插件的配置是什么。**你打印出来的任何一条配置，都可以用你自己的 patch 文件替换掉**——这句话就是第 09 篇的全部主题，这里先埋个种子。

如果你暂时不方便跑起来也不影响阅读，但强烈建议至少执行方式一。

## 本书怎么带你读

DSH 有近八千个文件，如果按目录结构平铺直叙地讲，只会重蹈"太专业、没逻辑、看不懂"的覆辙。我们换一种**构造式**的讲法：

> **假装这个系统不存在，你要亲手造一个。每造一步遇到的真实难题，就是每一章的起点；看 DSH 怎么解题，就是每一章的主体；解完题你能带走什么，就是每章结尾的"复刻清单"。**

整个旅程只有 15 站，地图如下（详见[导读](./README.md)）：

```
宏观     01 开篇 → 02 一条消息的一生
核心引擎 03 循环 → 04 会话日志 → 05 LLM 层 → 06 工具 → 07 安全
骨架形态 08 Cordis → 09 启动发行 → 10 Web 前端
认知增强 11 Subagent → 12 记账工具族 → 13 上下文管理
动手超越 14 复刻路线图 → 15 超越 DSH
```

贯穿全书的是三条原则（导读里有完整阐述），它们几乎能解释 DSH 的每一个设计决策：

1. **事实只记录一次，其余皆投影**——一切从 append-only 的会话事件流推导出来；
2. **扩展靠组合，不靠修改**——没有特权内核，所有注册都是可逆副作用；
3. **宁可失败，不可说谎**——fail-closed、schema 不撒谎、不变量硬断言。

以后每当你在某个细节里迷路，回到这三条原则上想想"它为什么要这样"，多半就能豁然开朗。
